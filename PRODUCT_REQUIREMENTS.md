# PRODUCT REQUIREMENTS

## Problem
A repository list does not communicate how six AI-agent projects differ architecturally. Recruiters need a fast narrative; engineers need inspectable evidence.

## Value
A memorable technical portfolio that explains what each system receives, decides, calls, stores, validates and returns.

## Requirements

### REQ-001 — Architectural narrative · Must
Home presents six ordered capability steps, not six equal cards.  
**Acceptance:** ACT → DELEGATE → COMPUTE → COMPOSE → VERIFY → CONNECT is visible and linked.

### REQ-002 — Recruiter scan path · Must
Home exposes thesis, proof strip, strongest projects, honesty summary and conditional CV/GitHub/contact actions.

### REQ-003 — Project index · Must
Filter projects by Tool, State, Transfer, AgentTool, Parallel, Sequential, Loop, RAG, MCP and A2A.  
**Empty:** “No project matches all selected patterns. Clear one filter.”

### REQ-004 — Six case studies · Must
Each includes thesis, problem, architecture, trace, decisions, limitations, roadmap and evidence footer.

### REQ-005 — Individual project art direction · Must
Follow `PROJECT_VIBE_SPECS.md`; do not merely recolor one shared template.

### REQ-006 — A2A System Explorer · Must
Select a preset, play or step through a simulated request and inspect routing, workflow, tool/data and artifact stages.

### REQ-007 — Simulation honesty · Must
The simulation label remains visible beside trace controls and inspector.

### REQ-008 — Evidence layer · Must
Claims carry an allowed evidence state and may link to verified source/test/screenshot/commit data.

### REQ-009 — Known limitations · Must
Limitations appear in every case study and on a consolidated evidence page.

### REQ-010 — Learning layer · Must
Glossary and four lessons: Agent vs chatbot; file anatomy; four multi-agent patterns; MCP vs A2A.

### REQ-011 — Responsive experience · Must
Core journey works at all specified viewports with no page-level overflow.

### REQ-012 — Accessibility · Must
Navigation, filters, project rows, presets and trace steps work by keyboard with visible focus.

### REQ-013 — Link safety · Must
Empty CV, GitHub, repository, dossier and contact URLs are hidden.

### REQ-014 — Content model · Must
Pages and diagrams are data-driven so a seventh project can be added without redesign.

### REQ-015 — Performance · Should
Target mobile LCP below 2.5 seconds in production testing. This is a budget, not a claimed result.

### REQ-016 — Source-code evidence · Should
Verified excerpts are 10–25 lines, annotated and linked to real files. Missing excerpts remain pending.

### REQ-017 — Print/dossier · Could
Case studies remain readable in print and may later generate a dossier.

### REQ-018 — Live demo · Later
Future backend may expose redacted, rate-limited live traces with real status and latency.
